Pattern of the day

The request is sent twice. Why is only one order made?The network timed out, so the app retried. The key is the answer.

Illustrative request logPOST /orders
try 1 · Idempotency-Key: ord_7f3a
→ 201 order created (reply lost)
try 2 · Idempotency-Key: ord_7f3a
→ 201 saved reply returned, no new order
orders created1
How: the client makes one key per action and reuses it on every retry. The server saves the first result and replays it for the same key.
Pattern as documented in Stripe's API docs
