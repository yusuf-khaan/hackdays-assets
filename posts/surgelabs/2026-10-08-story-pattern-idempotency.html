Idempotency key

noun · /ˌaɪ.dəmˈpoʊ.tən.si/ · backend pattern
A unique ID sent with a request, so doing it twice has the same effect as doing it once.
# network blips, the client retries
POST /payments  key="order-1042" → created
POST /payments  key="order-1042" → same result
# one charge, not two
Why it matters
01Retries become safe: no double charges, emails or orders.
02Queues and webhooks can deliver twice. Your system shrugs.
03Agents retry tool calls. Idempotent tools keep that harmless.
Retries will happen. We build backend automation and agent systems where they're safe by design.
